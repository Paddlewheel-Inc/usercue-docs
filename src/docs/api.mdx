The UserCue REST API lets you read and manage workspace feedback, boards, tags, settings, changelog data, and integrations from your own code.

## Quick start

## Base URL

The API is served by your UserCue workspace. Use its origin followed by `/api/v1`.

```text
https://your-usercue-host.example/api/v1
```

For a self-hosted workspace, replace the example origin with the URL where your UserCue server is reachable. All request paths in this guide are relative to `/api/v1`.

## Authentication

Create a key in **Settings → API keys**. UserCue displays the full key only once, immediately after creation. Store it somewhere secure; the key cannot be recovered later. You can edit its permissions or revoke it from Settings.

UserCue stores a hash of each key, not the original token. Keys do not currently expire automatically. They stop working when revoked, when their owner is suspended or deleted, or when the workspace is unavailable.

Send the key as a bearer token on every request:

```http
Authorization: Bearer uc_your_api_key
Content-Type: application/json
```

Do not put a key in a URL, query string, browser bundle, source repository, or client-side application. Use it from a trusted server and keep it in a secret manager or environment variable. Revoke a key immediately if it may have been exposed.

Every `/api/v1` route requires a valid API key, including endpoints whose data is otherwise public. Keys are workspace-specific and act as their owner. Creating feedback, comments, votes, and reactions through a key is attributed to that account; a `name` supplied in a request does not override the key owner.

## API-key permissions

A key can use only the permissions selected for that key and currently held by its owner. The server calculates the effective permissions on every request:

```text
effective permissions = key permissions ∩ owner's current role permissions
```

Changing the owner’s role takes effect immediately. The key cannot add privileges, including through API-key creation or permission updates. Any staff member with `dashboard` access can manage API keys. Keys created through the REST API can grant only permissions in the calling key's effective scope. Owners can see all workspace keys and revoke any of them; other staff members can see and revoke only their own keys.

Permission IDs:

| ID | Grants access to |
| --- | --- |
| `dashboard` | Staff workspace, changelog management, and staff-only post-comment deletion |
| `manage_posts` | Edit or delete posts and manage tags |
| `manage_boards` | Create, rename, and delete boards |
| `manage_settings` | Change general settings and configure sign-in providers |
| `manage_branding` | Change workspace branding |
| `manage_users` | View, change, and delete accounts; also read roles |
| `manage_roles` | Create, change, reorder, and delete roles; also read roles |
| `manage_staff` | Invite people and remove staff access |

An endpoint marked **API key** requires authentication but no additional permission. Endpoints marked with permissions require the key to have at least one of the listed permissions. Public board operations such as reading posts, posting feedback, commenting, voting, and reacting do not require a staff permission, but still require a valid API key.

Role administration is bounded by the caller's effective permissions. Creating a role or changing a role's permissions cannot grant a permission the caller does not have. Assigning a role to a user requires both `manage_users` and `manage_roles`; the assigned role must also stay within the caller's effective permissions. Only an Owner whose effective permissions include the full permission catalog can assign the Owner role. These checks apply to API keys as well as browser sessions.

## Requests and responses

Send JSON request bodies with `Content-Type: application/json`. Successful responses are JSON, except for the changelog RSS endpoint, which returns XML.

Timestamps such as `createdAt` and `updatedAt` are Unix timestamps in seconds. IDs are positive integers unless stated otherwise. The API does not currently provide a separate pagination envelope: list endpoints return arrays, with pagination parameters documented below where available.

Validation errors and malformed JSON return HTTP `400`. Other common responses include:

| Status | Meaning |
| --- | --- |
| `401` | Missing or invalid API key |
| `403` | The key is missing a required permission, the owner is suspended, a role change exceeds the caller's authority, or a workspace feature is disabled |
| `404` | The requested resource does not exist or is unavailable |
| `409` | A resource conflicts with an existing value, such as a duplicate board or tag name, or a vote is refused because the owner is out of votes (`code` is `vote_limit`) |
| `429` | The endpoint rate limit was exceeded |
| `500` | Unexpected server error |

Error responses generally include an `error` string. Validation responses may include structured issue details.

## Who am I

`GET /me` — **API key**

Returns the account the key acts as. Use it to confirm a key works and to see its owner's role.

```json
{
  "id": 3,
  "email": "sam@example.com",
  "name": "Sam",
  "avatarUrl": null,
  "roleId": 2,
  "roleName": "Staff",
  "roleIcon": null,
  "permissions": ["dashboard", "manage_posts"],
  "staff": true,
  "suspended": false,
  "hasPassword": true,
  "emailUpdates": true,
  "emailDigest": true
}
```

`permissions` lists the owner's role permissions. A key can use only the subset selected for it.

## Workflow

Statuses are workspace data, and they can be customized. Read them instead of hard-coding the five built-in IDs.

### List statuses

`GET /workflow` — **API key**

```json
[
  { "id": "open", "name": "Open", "icon": "default", "color": "#a8a29e", "category": "open" },
  { "id": "custom_8f1c…", "name": "Under review", "icon": "review", "color": "#7c3aed", "category": "open" }
]
```

`category` is one of `open`, `planned`, `in_progress`, `complete`, or `closed`. The category decides how UserCue treats a status. See [Custom statuses](/workspace/statuses#custom-statuses).

### Create or update a status

`POST /workflow` — **`manage_settings`**

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `name` | string | Yes | Trimmed; 1–40 characters |
| `icon` | string | Yes | One of the icon names the Workflow settings tab offers, for example `default`, `circle`, `rocket`, `star`, `review` |
| `color` | string | Yes | `#RRGGBB` |
| `category` | string | Yes (create only) | `open`, `planned`, `in_progress`, `complete`, or `closed` |

Returns the status with HTTP `201`. The ID is generated and starts with `custom_`.

`PATCH /workflow/:id` — **`manage_settings`** takes `name`, `icon`, and `color`, all required, and returns the updated status. A status's category cannot change after it is created. Unknown IDs return `404`.

## Boards

### List boards

`GET /boards` — **API key**

Returns an array ordered by board ID:

```json
[
  { "id": 1, "slug": "ideas", "name": "Ideas" }
]
```

### Create a board

`POST /boards` — **`manage_boards`**

```json
{ "name": "Ideas" }
```

`name` is trimmed, required, and 1–40 characters. The server creates a lowercase slug by replacing runs of non-alphanumeric characters with hyphens and trimming hyphens from either end. Names that produce an empty slug are rejected. Duplicate slugs return `409`.

Returns the new board object with HTTP `201`.

### Rename a board

`PATCH /boards/:slug` — **`manage_boards`**

```json
{ "name": "Product ideas" }
```

`name` is trimmed, required, and 1–40 characters. Renaming updates the display name; it does not regenerate the slug. Returns the updated board or `404` if the slug is unknown.

### Delete a board

`DELETE /boards/:slug` — **`manage_boards`**

Returns `{ "ok": true }` when deleted, or `404` if the board does not exist.

## Feedback posts

### List posts

`GET /posts` — **API key**

| Query parameter | Type and allowed values | Default |
| --- | --- | --- |
| `board` | Board slug | All boards |
| `status` | A status ID from `GET /workflow`. The built-in IDs are `open`, `planned`, `in_progress`, `complete`, `closed` | All statuses |
| `category` | `open`, `planned`, `in_progress`, `complete`, `closed`. Matches every status in that category, including custom ones | All categories |
| `tag` | Tag ID | Any tag |
| `assignee` | A staff user ID, or `none` for unassigned posts | Anyone |
| `minVotes` | Integer from 0 to 1000000 | `0` |
| `sort` | `top`, `new`, `priority` | `top` |
| `q` | Search text, maximum 100 characters | No search |
| `limit` | Integer from 1 to 100 | `50` |
| `offset` | Integer from 0 to 100000 | `0` |

`top` sorts by vote count, then newest first. `new` sorts newest first. `priority` sorts by [priority score](/workspace/triage#priority-score), highest first, and posts without a score come last. It needs a `dashboard` key; for other keys it behaves like `top`. Search matches the title and body. Returns an array of post objects. Each object includes:

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | integer | Post ID |
| `title`, `body` | string | Post title and sanitized HTML body |
| `status` | string | One of the status values above |
| `authorName` | string | Display name of the author |
| `authorAvatar` | string or `null` | Author avatar URL |
| `authorRole` | object or `null` | Staff role `{ "name", "iconUrl" }` |
| `voteCount`, `commentCount` | integer | Current totals |
| `createdAt` | integer | Unix timestamp in seconds |
| `board` | string | Board slug |
| `boardName` | string | Board display name |
| `voted` | boolean | Whether this API key has voted for the post |
| `tags` | array | `{ "id", "name", "color" }` objects |
| `assignee` | object or `null` | `{ "id", "name", "avatarUrl" }` |

Example:

```json
[
  {
    "id": 42,
    "title": "Add keyboard shortcuts",
    "body": "<p>Speed up common actions.</p>",
    "status": "open",
    "authorName": "Alex",
    "authorAvatar": null,
    "authorRole": null,
    "voteCount": 7,
    "commentCount": 2,
    "createdAt": 1793556000,
    "board": "ideas",
    "boardName": "Ideas",
    "voted": false,
    "tags": [{ "id": 3, "name": "Accessibility", "color": "blue" }],
    "assignee": null
  }
]
```

### Get status counts

`GET /posts/counts` — **API key**

Optional query parameter: `board` (board slug). Returns counts keyed by every status. A status with no posts is `0`.

```json
{
  "open": 12,
  "planned": 3,
  "in_progress": 2,
  "complete": 8,
  "closed": 1
}
```

### Create a post

`POST /posts` — **API key**

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `board` | string | Yes | Existing board slug |
| `title` | string | Yes | Trimmed; 1–140 characters |
| `body` | string | No | Trimmed; maximum 8000 characters; defaults to empty |
| `name` | string | No | Trimmed; 1–60 characters; ignored when using an API key because the key owner is the author |
| `tagIds` | integer array | No | Positive tag IDs; maximum 8 distinct tags; tags must exist and customer tags must be enabled |

```json
{
  "board": "ideas",
  "title": "Add keyboard shortcuts",
  "body": "<p>Speed up common actions.</p>",
  "tagIds": [3]
}
```

The server sanitizes HTML in `body`. A newly created post starts with status `open` and receives a vote from the API key. It returns the post object with HTTP `201`. If customer tags are required, include at least one valid `tagId`.

### Get a post

`GET /posts/:id` — **API key**

Returns the post object described in **List posts**, with two additional arrays:

- `comments`: comment objects with `id`, `parentId`, `authorName`, `authorAvatar`, `authorRole`, `body`, `isTeam`, and `createdAt`.
- `history`: status-change objects with `id`, `status`, `actorName`, `actorAvatar`, and `createdAt`.

Returns `404` when the post does not exist.

### Vote for a post

`POST /posts/:id/vote` — **API key**

No request body. This toggles the vote associated with this API key and returns:

```json
{ "voteCount": 8, "voted": true }
```

This operation is not idempotent: a second call with the same key removes its vote. If the workspace has a vote limit and the owner has none left, adding a vote returns `409` with `code` set to `vote_limit`. See [Vote budget](#vote-budget).

### List voters

`GET /posts/:id/voters` — **API key**

Returns vote totals and up to 12 named voters:

```json
{
  "total": 8,
  "anonymous": 1,
  "people": [{ "name": "Alex", "avatarUrl": null }]
}
```

### Add a comment

`POST /posts/:id/comments` — **API key**

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `body` | string | Yes | Trimmed; 1–2000 characters |
| `name` | string | No | Trimmed; 1–60 characters; ignored for an API key |
| `parentId` | integer | No | Positive ID of a comment on this post |

```json
{ "body": "This would help our team.", "parentId": 15 }
```

The server sanitizes the body and attributes the comment to the key owner. Returns the comment object with HTTP `201`. A parent comment from another post is rejected.

### Delete a comment

`DELETE /posts/:id/comments/:commentId` — **`dashboard`**

No request body. A dashboard key can delete any comment on the specified post. Returns `{ "ok": true }` or `404` if the comment is not on that post.

### Update a post

`PATCH /posts/:id` — **`manage_posts`**

Send one or more fields:

| Field | Type | Constraints and behavior |
| --- | --- | --- |
| `board` | string | Trimmed, 1–80 characters; must be an existing slug |
| `status` | string | A status ID from `GET /workflow`, such as `planned` or a custom `custom_...` ID |
| `title` | string | Trimmed; 1–140 characters |
| `body` | string | Trimmed; maximum 8000 characters; sanitized by the server |
| `assigneeId` | integer or `null` | Positive active staff user ID; `null` clears assignment; assignment must not be Off |
| `tagIds` | integer array | Positive IDs, at most 8 distinct tags, all must exist |
| `impact` | integer or `null` | 1–5, or `null` to clear. Returns `400` when [triage](/workspace/triage) is off for the post's board |
| `effort` | integer or `null` | 1–5, or `null` to clear. Same rule as `impact` |

Status changes are recorded in history, can send chat and webhook notifications (`post.status_changed`), and tell voters when a post reaches a Complete status. When assignment mode is Automatic, changing status to `planned` can assign the next eligible staff member. All fields are validated before updates are applied; if validation fails, none of the requested changes are saved. Returns the updated post object.

### Delete a post

`DELETE /posts/:id` — **`manage_posts`**

Returns `{ "ok": true }`.

### Find similar posts

`GET /posts/similar?q=<text>` — **API key**

Returns up to five existing posts that match the words in `q`, which is trimmed and limited to 300 characters. Use it to deflect duplicates before you create a post.

```json
{
  "posts": [
    { "id": 42, "title": "Add keyboard shortcuts", "status": "open", "voteCount": 7, "board": "ideas" }
  ]
}
```

A short or generic `q` returns an empty array. Limited to 30 requests per minute.

### Vote budget

`GET /posts/budget` — **API key**

Returns how many active votes the key's owner has used against the workspace [vote limit](/settings/general#voting).

```json
{ "limit": 10, "used": 4 }
```

`limit` is `0` when there is no limit. When the owner is at the limit, `POST /posts/:id/vote` returns `409` with `{ "error": "...", "code": "vote_limit" }`. Removing a vote is always allowed.

### Merge a post

`POST /posts/:id/merge` — **`manage_posts`**

```json
{ "targetId": 42 }
```

Merges the post in the path into `targetId`. Votes, comments, tags, internal notes, and changelog links move to the target, and the merged post is deleted. Requests for the old ID now resolve to the target, so existing links keep working. Returns `{ "targetId": 42 }`.

`400` means the IDs are the same. `404` means either post does not exist. A merge sends the `post.merged` [webhook](/integrations/webhooks) and is written to the [audit log](/settings/audit-log). See [Similar posts and merging](/boards/duplicates).

## Triage

These endpoints need `dashboard`. They return `404` for a post where [triage](/workspace/triage) is turned off. To set the scores, `PATCH /posts/:id` with `impact` and `effort`.

### Read triage data

`GET /posts/:id/triage` — **`dashboard`**

```json
{
  "impact": 4,
  "effort": 2,
  "score": 26,
  "notes": [
    { "id": 9, "authorName": "Sam", "body": "Asked for by Acme.", "createdAt": 1793556000, "canDelete": true }
  ]
}
```

`score` is `(votes + 1) × impact ÷ effort`, rounded to one decimal, or `null` when either value is missing.

### Add a note

`POST /posts/:id/notes` — **`dashboard`**

```json
{ "body": "Asked for by Acme." }
```

`body` is trimmed, 1–2000 characters. Returns the note with HTTP `201`. Limited to 30 requests per minute.

### Delete a note

`DELETE /posts/:id/notes/:noteId` — **`dashboard`**

A key can delete notes its owner wrote. `manage_posts` can delete anyone's. Returns `{ "ok": true }`, `403` if the note belongs to someone else, or `404`.

## Tags

Tag colors are `pink`, `rose`, `coral`, `amber`, `lime`, `green`, `teal`, `sky`, `blue`, `violet`, and `stone`.

### List tags

`GET /tags` — **API key**

Returns an array of `{ "id", "name", "color" }` objects.

### Create a tag

`POST /tags` — **`manage_posts` or `manage_settings`**

```json
{ "name": "Needs review", "color": "amber" }
```

`name` is trimmed and 1–24 characters. `color` must be one of the listed values. Duplicate names return `409`. Returns the tag with HTTP `201`.

### Update a tag

`PATCH /tags/:id` — **`manage_posts` or `manage_settings`**

Send either or both optional fields: `name` (trimmed, 1–24 characters) and `color` (a listed tag color). Returns the updated tag or `404`.

### Delete a tag

`DELETE /tags/:id` — **`manage_posts` or `manage_settings`**

Returns `{ "ok": true }`. If tags are required for feedback, the last tag cannot be deleted until that setting is turned off.

## Workspace settings

### Read workspace settings

`GET /settings` — **`dashboard`**

Returns a settings snapshot with the following fields:

- Workspace behavior: `allowGuestFeedback`, `changelogEnabled`, `changelogComments`, `changelogReactions`, `changelogRssUrl`, `assignmentMode`, `oauthOnly`, `customerTags`, and `customerTagsRequired`.
- Branding: `accent`, `logoUrl`, `logoDarkUrl`, `siteName`, `siteDescription`, `faviconUrl`, and `shareImageUrl`.
- Email: `resend` (`configured`, `enabled`, `from`, `keyHash`, `fromEnv`) and `smtp` (`configured`, `enabled`, `host`, `port`, `user`, `from`, `secure`, `passConfigured`, `fromEnv`).
- Chat notifications: `slack`, `discord`, and `teams`, each with `configured`, `enabled`, and `keyHash`.
- Engagement: `notifyVoters`, `voteLimit`, and `digest` (`enabled`, `day`, `hour`, `ready`).
- Triage: `triage` with `enabled` and a `boards` array of `{ "slug", "name", "enabled" }`.
- Integrations: `inbound` (`enabled`, `configured`, `keyHash`, `url`, `resendReady`) and `ai` (`enabled`, `configured`, `baseUrl`, `model`, `keyHash`).
- Staff: `staff` and `invites` arrays. These include staff email addresses and invite URLs, so the arrays are returned only to keys that also have `manage_staff`; otherwise they are empty.

Secret values are never returned. `keyHash` is only a short fingerprint, not a credential.

### Update general settings

`PATCH /settings` — **`manage_settings`**

All fields are optional; send only the values you want to change.

| Field | Type | Allowed values / constraints |
| --- | --- | --- |
| `allowGuestFeedback` | boolean | Enable or disable guest feedback |
| `changelogEnabled` | boolean | Enable or disable changelog |
| `changelogComments` | boolean | Enable or disable changelog comments |
| `changelogReactions` | boolean | Enable or disable changelog reactions |
| `assignmentMode` | string | `off`, `manual`, `auto` |
| `resendEnabled` | boolean | Requires a configured Resend key and from address |
| `resendFrom` | string | Maximum 200 characters |
| `resendApiKey` | string | Maximum 200 characters; not returned by the API |
| `smtpHost` | string | Maximum 200 characters; must be configured together with `smtpFrom` |
| `smtpEnabled` | boolean | Requires an SMTP host and from address |
| `smtpPort` | integer | 1–65535 |
| `smtpUser` | string | Maximum 200 characters |
| `smtpPass` | string | Maximum 200 characters; not returned by the API |
| `smtpFrom` | string | Maximum 200 characters; must be configured together with `smtpHost` |
| `smtpSecure` | boolean | Use a secure SMTP connection |
| `discordEnabled` | boolean | Requires a configured Discord webhook |
| `discordWebhookUrl` | string | Maximum 200 characters; must be a valid Discord webhook URL |
| `teamsEnabled` | boolean | Requires a configured Teams webhook |

## API-key management

Any staff member with `dashboard` access can manage API keys. Non-Owners can only list, edit, and revoke their own keys. Owners can list all workspace keys and revoke any key, but can edit permissions only on keys they own. The full token is returned only by key creation.

### List keys

`GET /settings/api-keys` — **Staff (`dashboard`)**

Returns an array of keys containing `id`, `ownerId`, `canRevoke`, `name`, `prefix`, `permissions`, `createdAt`, `lastModifiedAt`, `lastUsedAt`, and `createdBy` (`name`, `avatarUrl`). Non-Owners receive their own keys; Owners receive all workspace keys. `canRevoke` indicates whether the caller can revoke the key. `lastUsedAt` is `null` until first use. Full key values are never returned.

### Create a key

`POST /settings/api-keys` — **Staff (`dashboard`)**

```json
{ "name": "Website integration", "permissions": ["manage_posts"] }
```

`name` is trimmed, required, and 1–60 characters. `permissions` is optional and defaults to `[]`; if provided, each entry must be one of the permission IDs above and assigned to the key owner. Duplicate entries are removed.

Returns the key metadata plus `key` exactly once, with HTTP `201`. Save the token securely before leaving the response.

### Change key permissions

`PATCH /settings/api-keys/:id` — **Staff key owner**

```json
{ "permissions": ["manage_posts", "manage_boards"] }
```

`permissions` is required. Each value must be a valid permission held by the owner. This changes the key’s effective access immediately and updates `lastModifiedAt`. Returns the updated key metadata, never its token.

### Revoke a key

`DELETE /settings/api-keys/:id` — **Staff key owner or workspace Owner**

Returns `{ "ok": true }`. Subsequent requests made with the key are rejected.

## Users, roles, and staff

These endpoints are intended for trusted workspace automation. They can change account access, roles, and staff membership.

### Users

- `GET /settings/users` — **`manage_users`**. Returns `{ "users": [...] }`; each user includes `id`, `email`, `name`, `avatarUrl`, `createdAt`, `suspended`, `roleId`, `roleName`, and `staff`.
- `PATCH /settings/users/:id` — **`manage_users`**. Send optional `suspended` (boolean) and/or `roleId` (integer). Changing a role additionally requires `manage_roles`; the assigned role may contain only permissions in the caller's effective scope. Only an Owner whose effective scope includes every permission can assign the Owner role. You cannot change your own account here. The last owner cannot be suspended or reassigned.
- `DELETE /settings/users/:id` — **`manage_users`**. Returns `{ "ok": true }`. You cannot delete yourself or the last owner.

### Roles

- `GET /settings/roles` — **`manage_roles` or `manage_users`**. Returns `{ "roles": [...], "catalog": [...] }`. A role has `id`, `name`, `locked`, `permissions`, `iconUrl`, and `userCount`. Catalog entries have `id`, `label`, and `description`.
- `POST /settings/roles` — **`manage_roles`**. Body: required `name` (trimmed, 1–40 characters), optional `permissions` (array of permission IDs, defaults to empty), optional `iconUrl` (maximum 500 characters). A role can grant only permissions in the caller's effective scope. Duplicate role names return `409`. Returns the updated role payload with HTTP `201`.
- `PATCH /settings/roles/order` — **`manage_roles`**. Body: `{ "ids": [1, 2] }`. Provide every role ID exactly once; array length must be 1–100.
- `PATCH /settings/roles/:id` — **`manage_roles`**. Optional fields: `name` (trimmed, 1–40 characters), `permissions` (permission IDs), and `iconUrl` (maximum 500 characters). Permission updates may grant only permissions in the caller's effective scope. Locked roles cannot have their permissions changed. Returns the updated role payload.
- `DELETE /settings/roles/:id` — **`manage_roles`**. Locked roles and roles assigned to users cannot be deleted. Returns the updated role payload.

### Staff invites and removal

- `POST /settings/invites` — **`manage_staff`**. Body: `{ "email": "person@example.com" }`. Email is validated and normalized to lowercase. A new invite response includes `id`, `email`, `url`, `expiresAt`, and `emailSent`. If the email already belongs to a non-staff account, that account is promoted and the response is `{ "promoted": true, "email", "name" }`. Existing staff addresses return `409`.
- `DELETE /settings/invites/:id` — **`manage_staff`**. Revokes a pending invite and returns an updated settings snapshot.
- `DELETE /settings/staff/:id` — **`manage_staff`**. Removes dashboard access by moving the person to the Member role. You cannot remove yourself, the last owner, or the last dashboard user. Returns an updated settings snapshot.

Treat invite `url` values as credentials: anyone with an unused invite URL can complete that invite.

## Sign-in provider settings

Provider IDs are `github`, `discord`, `google`, `roblox`, and `azure`. These endpoints configure sign-in; they do not initiate an OAuth flow.

- `GET /auth/providers` — **`manage_settings`**. Returns an array of providers with `id`, `label`, `console`, `redirectField`, `hint`, `redirectUrl`, `configured`, `enabled`, `allowSignup`, `clientId`, and `secretHash`. Secret values are never returned; `secretHash` is only a short fingerprint.
- `PUT /auth/providers/:provider` — **`manage_settings`**. Body: required `clientId` (1–200 characters), optional `secret` (maximum 400 characters), optional `enabled` (boolean, defaults to `false`), and optional `allowSignup` (boolean, defaults to `false`). A `secret` is required on first configuration and can be omitted to retain the saved secret. Returns `{ "ok": true, "secretHash": "..." }`.
- `DELETE /auth/providers/:provider` — **`manage_settings`**. Removes the provider and returns `{ "ok": true }`.

Unknown provider IDs return `400`.

## Changelog

Changelog visibility and interactions follow the workspace’s `changelogEnabled`, `changelogComments`, and `changelogReactions` settings.

### List entries

`GET /changelog` — **API key**

When enabled, returns `enabled`, `commentsEnabled`, `reactionsEnabled`, `rssUrl`, and an `entries` array. Each entry includes `id`, `title`, `body`, `authorName`, `authorAvatar`, `authorRole`, `commentCount`, `reactions`, `contributors`, `linkedPost`, `imageUrl`, `createdAt`, and `updatedAt`. `rssUrl` is only populated for a staff key. If the changelog is disabled, a non-staff key receives an empty entries array and disabled feature flags.

`body` contains sanitized HTML. `linkedPost` is either `null` or `{ "id", "title" }`. Contributors are `{ "id", "name", "avatarUrl" }`. Each reaction contains `id`, `count`, `mine`, and up to 12 `{ "name", "avatarUrl" }` people.

### RSS feed

`GET /changelog/rss` — **API key**

Returns RSS 2.0 XML when the changelog is enabled; otherwise returns `404`.

### List contributors

`GET /changelog/people` — **`dashboard`**

Returns `{ "people": [...] }`, where each person has `id`, `name`, and `avatarUrl`. Suspended accounts are excluded.

### Create an entry

`POST /changelog` — **`dashboard`**

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `title` | string | Yes | Trimmed; 1–140 characters |
| `body` | string | No | Maximum 8000 characters of HTML; defaults to empty |
| `markdown` | string | No | Maximum 8000 characters. Rendered with the [changelog markdown](/changelog/markdown) dialect. Takes the place of `body` |
| `publicationStatus` | string | No | `draft`, `scheduled`, or `published`. Defaults to `published` |
| `publishAt` | integer | When `scheduled` | Unix timestamp in seconds, in the future. Only valid with `scheduled` |
| `postId` | positive integer or `null` | No | Links an existing feedback post |
| `imageUrl` | string | No | Maximum 200 characters; empty or a UserCue upload path |
| `contributorIds` | integer array | No | Positive user IDs; at most 20; defaults to empty |

The authenticated key owner is recorded as author. Returns the created entry with HTTP `201`.

```json
{
  "title": "v1.4.0",
  "markdown": "## New\n- Dark mode for the embed widget\n\n## Fixed\n- Search ignored accents",
  "postId": 42,
  "publicationStatus": "scheduled",
  "publishAt": 1793559600
}
```

Entries created through the API are published right away unless you set `publicationStatus`. Publishing sends the `changelog.published` [webhook](/integrations/webhooks) and, when `postId` is set, tells the post's voters. Drafts are visible only to staff. Entries now include `publicationStatus` and `publishedAt`, and a `markdown` field holding the source text when the entry was written in markdown, or an empty string otherwise.

### Get an entry

`GET /changelog/:id` — **API key**

Returns the entry fields above, plus `enabled`, `commentsEnabled`, `reactionsEnabled`, `rssUrl`, and `comments`. `comments` is empty if comments are disabled; otherwise each comment includes `id`, `authorName`, `authorAvatar`, `authorRole`, `body`, `isTeam`, `createdAt`, and `canDelete`.

### Update or delete an entry

- `PATCH /changelog/:id` — **`dashboard`**. Send any subset of `title` (trimmed, 1–140 characters), `body` (maximum 8000) or `markdown` (maximum 8000; sending `body` clears the stored markdown), `publicationStatus` and `publishAt` (as above; an entry that is already published keeps its date), `postId` (positive integer or `null`), `imageUrl` (maximum 200; empty or an upload path), and `contributorIds` (at most 20 positive user IDs). Returns the updated entry. An empty patch is rejected.
- `DELETE /changelog/:id` — **`dashboard`**. Returns `{ "ok": true }`.

### Changelog comments

- `POST /changelog/:id/comments` — **Authenticated key owner**. Body: `{ "body": "..." }`; body is trimmed, required, and 1–2000 characters. Requires changelog comments to be enabled. Returns the comment with HTTP `201`.
- `DELETE /changelog/:id/comments/:commentId` — **Authenticated key owner**. Deletes your own comment; a key with `dashboard` can delete any comment. Returns `{ "ok": true }`.

### Changelog reactions

`POST /changelog/:id/reactions` — **Authenticated key owner**

Body: `{ "reaction": "heart" }`. Reaction IDs are `up`, `party`, `heart`, and `rocket`. This toggles that reaction for the key owner and returns `{ "reactions": [...] }`. Reactions must be enabled in workspace settings.

```json
[
  {
    "id": 1,
    "name": "Ticketing",
    "urlPreview": "https://hooks.example.com/…",
    "events": ["post.created", "post.status_changed"],
```

The full URL and the secret are never returned after creation.

`POST /integrations/webhooks`

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `name` | string | Yes | Trimmed; 1–60 characters |
| `url` | string | Yes | `http` or `https` URL without a username or password; maximum 2000 characters |

### Import posts

`POST /integrations/import/posts`

Imports up to 200 rows per request. Send a larger file as several requests. For the matching rules and limits, see [Import feedback](/integrations/import).

```json
{
  "rows": [
    {
      "title": "Dark mode",
      "body": "Please add a dark theme.",
      "status": "Planned",
      "board": "Ideas",
      "authorName": "Alex",
      "authorEmail": "alex@example.com",
```

All fields in a row are required. Use empty strings, `0`, an empty array, or `null` for `createdAt` when you have no value. Titles are required and trimmed to 1–1000 characters. A batch whose rows hold more than 100,000 votes in total returns `400`.

Returns the outcome:

```json
{ "created": 1, "skipped": 0 }
```

When your whole import is done, call `POST /integrations/import/done` with `{ "count": 1 }`, using the total created. It writes one `import.posts` line to the audit log.

## Rate limits

Limits are per API key, HTTP method, and registered endpoint template, per running server process. They reset after the stated 60-second window. For example, alternate numeric spellings such as `/posts/01/comments` and `/posts/1/comments` share the same route bucket. Counters are held in process memory and are not shared across multiple server processes.

| Operation | Limit |
| --- | --- |
| `POST /posts` | 10 requests / minute |
| `POST /posts/:id/comments` | 20 requests / minute |
| `POST /posts/:id/vote` | 60 requests / minute |
| `GET /posts/:id/voters` | 120 requests / minute |
| `GET /posts/similar` | 30 requests / minute |
| `POST /posts/:id/notes` | 30 requests / minute |
| `POST /changelog` | 20 requests / minute |
| `POST /changelog/:id/comments` | 20 requests / minute |
| `POST /changelog/:id/reactions` | 60 requests / minute |

When a limit is exceeded, the API returns `429` with `{ "error": "Too many requests" }`.

## Recipes

Replace the host, key, and slugs with values from your workspace.

### Create feedback from another system

```bash
curl --request POST \
  --url 'https://feedback.example.com/api/v1/posts' \
  --header 'Authorization: Bearer uc_your_api_key' \
  --header 'Content-Type: application/json' \
  --data '{
    "board": "ideas",
    "title": "Add keyboard shortcuts",
    "body": "<p>Speed up common actions.</p>"
  }'
```

### Check for duplicates first

```js
const params = new URLSearchParams({ q: "keyboard shortcuts" });
const { posts } = await usercue(`/posts/similar?${params}`);

if (posts.length > 0) {
  await usercue(`/posts/${posts[0].id}/vote`, { method: "POST" });
} else {
  await usercue("/posts", {
    method: "POST",
    body: JSON.stringify({ board: "ideas", title: "Add keyboard shortcuts" }),
  });
}
```

### Read every post

The list endpoint returns at most 100 posts per call. Page with `limit` and `offset` until a page comes back short:

```js
async function* allPosts(filter = {}) {
  const limit = 100;
  for (let offset = 0; ; offset += limit) {
    const params = new URLSearchParams({ ...filter, limit, offset });
    const page = await usercue(`/posts?${params}`);
    yield* page;
    if (page.length < limit) return;
  }
}

for await (const post of allPosts({ category: "planned", sort: "new" })) {
  console.log(post.id, post.title, post.voteCount);
}
```

### Ship a release from CI

Create the entry as markdown and link it to the suggestion you shipped. Publishing it tells the people who voted.

```bash
curl --request POST \
  --url "$USERCUE_URL/api/v1/changelog" \
  --header "Authorization: Bearer $USERCUE_KEY" \
  --header 'Content-Type: application/json' \
  --data "$(jq -n --arg markdown "$(cat RELEASE_NOTES.md)" '{title: "v1.4.0", markdown: $markdown, postId: 42}')"
```

### Move a post when a ticket closes

Pair a [webhook](/integrations/webhooks) from your ticketing tool with a status change:

```js
await usercue(`/posts/${postId}`, {
  method: "PATCH",
  body: JSON.stringify({ status: "complete" }),
});
```

The key needs `manage_posts`. Look up status IDs with `GET /workflow` if you use custom statuses.

### Handle errors and limits

Every error has an `error` string. On `429`, wait and retry. On `409` from a vote, read `code`:

```js
const response = await fetch(`${base}/posts/42/vote`, { method: "POST", headers });
if (response.status === 409) {
  const { code } = await response.json();
  if (code === "vote_limit") console.log("Out of votes");
}
```

## Versioning and compatibility

The `/api/v1` prefix identifies the current API version. This reference describes the endpoints currently mounted under that prefix. The API reuses UserCue’s workspace handlers, so workspace feature settings, role changes, validation, and business rules apply to API requests as well as browser requests.
